What this is

The wall‑clock cost of one phase‑1 MS‑PSF fusion pass (fusion.mspsf), timed with and without the vectorization applied to fusion.py and geometry.py. The before bar runs verbatim pre‑vectorization code (commit 6b05baaa): Python double‑loops for the affinity/kappa matrices and a per‑pair Shapely IoU. The after bar is the shipped code — broadcast numpy and a single batched GEOS call.

The Kinematic‑Dynamic orientation step is excluded: mspsf is driven with kds_scores=None, so _orient_with_kds never runs in either arm and the comparison is the vectorization alone.

The x‑axis is ordered by total detections n (senders × objects per sender), which is what the fusion cost scales with — so the widening gap left‑to‑right is the improvement scaling with load. A log scale is used because the four scenes span three orders of magnitude; the exact speedup is printed above each pair.

This page never measures anything: scripts/make_fusion_speedup_viz.py times both arms in the emulated‑x86 ros2_dev container (reporting the median, the 25th–75th percentiles, and the best run, since single runs there swing ~2×) and writes fusion_speedup_data.js, loaded here as a plain script tag so the page opens over file:// with no server. Re‑run the script after changing fusion.py/geometry.py to refresh it.
