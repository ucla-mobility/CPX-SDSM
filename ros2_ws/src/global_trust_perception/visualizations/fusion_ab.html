What this is

End-to-end latency of the global trust pipeline (flush_frame), timed with the MS-PSF speed rewrites on (modified, shipped vectorized) versus off (reference, pre-optimization Python loops); kds-orientation is present in both, so this isolates the speed rewrites. "Matching" is the MS-PSF phase-1 fusion stage — the clustering step is the matching. Charts sweep two ways: over agent count (objects fixed) and over object count (agents fixed). Lines are colored by machine and dashed by variant (solid = modified, dashed = reference). A line is a fitted power-law curve (a·xb) when the stage scales non-linearly; a series that scales about linearly just connects its measured points.

Frames are synthetic (there is no multi-agent dataset): benchmark_stages.py lays objects on a 15 m grid, has every agent and ego observe each with 0.2 m noise (so the correct matching is known), and disagrees on ~15% of labels (so the fusion kappa term does real work). It measures latency, not accuracy. Container timings on an emulated-x86 host are inflated — compare machines of like kind.

This page never reads the benchmark dumps: tools/fusion_ab/compare_stages.py --viz-data reads them and writes fusion_ab_data.js, loaded here as a plain script tag so it opens over file://. Re-run it after new sweeps (on any machine) to refresh — reloading this page alone will not.
